# 운영 시연 실행기

운영 사이트(https://paldo-gotgan-fe.vercel.app)에서 가입부터 정산까지 돈이 한 바퀴 도는 흐름을 Playwright로 실행해요.
구매자·판매자·관리자 창을 따로 띄우고, 장면에 맞는 창 하나만 화면 왼쪽 75%에 펼쳐요(나머지는 최소화). 오른쪽 25%에 터미널을 두고 Enter로 장면을 넘겨요.

## 준비 (처음 한 번)

Node 20 이상이면 돼요(Playwright 요구 사항. 앱 테스트와 달리 Node 24가 아니어도 괜찮아요).

```bash
cd demo
npm install                      # Playwright 패키지
npx playwright install chromium  # Playwright가 쓰는 Chromium
```

준비할 것:

- **관리자 계정**: 운영 관리자 아이디·비밀번호. 코드에는 없고, 실행할 때 창에서 직접 로그인해요.
- **상품 사진(선택)**: `assets/product.png`를 실제 사진으로 바꾸면 화면이 보기 좋아요. jpg로 바꾸면 `scenes.mjs`의 `PRODUCT_IMAGE` 파일 이름도 바꿔요.

## 실행

`demo` 폴더에서:

```bash
./demo.sh                # 새 시연 계정으로 1번 장면부터
./demo.sh --from 5       # state.json의 계정으로 5번 장면부터 이어서
./demo.sh --auto         # Enter 없이 장면을 이어서 실행(실패하거나 확인이 필요하면 멈춤)
./demo.sh --record       # videos/에 역할별 영상도 남김
```

`frontend` 폴더에서는 `./demo/demo.sh`로 불러요. `demo.sh`는 화면 크기 기본값(맥북 1728×1080)을 넣고 `node run.mjs`를 실행해요. 다른 화면이면 `DEMO_SCREEN_W=1920 ./demo.sh`처럼 덮어써요.

> 경로에 한글 폴더(`프로그래머스_단기심화`)가 있어서 붙여 넣은 `cd`가 실패할 수 있어요. 그럴 땐 `cd ~/Documents/*/200Ok_project/frontend/demo`처럼 `*`로 대신해요.

### 진행 순서

1. 실행하면 터미널에 이번 시연 계정(구매자 `db…`, 판매자 `ds…`, 비밀번호)이 찍히고 창 3개가 떠요.
2. **관리자 창에서 직접 로그인해요.** 로그인하면 자동으로 다음으로 넘어가요.
3. 터미널에 `▶ 1. 구매자 회원가입·로그인 [Enter 시작 · s 건너뛰기 · q 끝내기]`가 나오면 Enter를 눌러요. 장면이 끝나면 `✅`가 찍히고 다음 장면을 기다려요.
4. **5번 장면 끝에서 직접 해요.**
   - 첫 충전 약관 창: 전체 동의 → [동의하고 충전하기]
   - 토스 결제창: 테스트 결제
   - 충전 완료 화면이 뜨면 자동으로 이어가요.
5. 10번까지 끝나면 Enter로 창을 닫아요.

장면이 실패하면 `❌ 장면: 오류`가 찍히고 `r 다시 · s 다음 장면으로 · q 끝내기`를 물어봐요. 코드를 고쳤다면 `r`로는 반영되지 않아요. `q`로 끝내고 `--from N`으로 다시 시작해요.

## 장면

| 장면 | 창 | 내용 |
|---|---|---|
| 1 | 구매자 | 회원가입 → 로그인 (기본 배송지는 API로 저장) |
| 2 | 판매자 | 로그인 → 입점 신청 |
| 3 | 관리자 | 심사 시작 → 승인 → 판매자 창이 권한을 받고 센터로 이동 (상점 프로필은 API로 등록) |
| 4 | 판매자 | 상품 등록 (사진·설명·옵션·판매 중·공개) |
| 5 | 구매자 | 담기 → 장바구니 → 주문서(예치금 부족) → 부족한 금액만큼 충전 → **약관 동의·토스 결제는 직접** |
| 6 | 구매자 | 충전 완료에서 주문서로 돌아가기 → 예치금 결제 |
| 7 | 판매자 | 송장 등록 (가짜 택배사가 몇 초 뒤 배송 완료로 바꿔요) |
| 8 | 구매자 | 구매확정 |
| 9 | 관리자 | 대기 건너뛰고 정산 실행 |
| 10 | 판매자 | 지갑 잔액 → 정산 상세 |

화면 밖에서 API로 처리하는 것: 판매자 계정 가입, 구매자 기본 배송지(우편번호 찾기는 외부 팝업이라), 상점 프로필.

## 이어 하기 (`--from N`)

- 장면이 끝날 때마다 계정·상품 번호·주문 번호를 `state.json`에 저장해요. `--from N`은 이 값으로 N번부터 해요.
- 창을 새로 띄우므로 관리자는 다시 로그인하고, 구매자·판매자는 스크립트가 다시 로그인해요.
- `--from` 없이 실행하면 새 계정을 만들고 `state.json`을 덮어써요.
- 장면별 조건:
  - 3번: 이미 심사 중인 신청이면 상세로 바로 가서 승인해요.
  - 5번: 구매자 예치금이 상품값보다 적어야 해요(주문서에 '예치금 부족'이 떠야 함). 이미 충전한 계정이면 `--from 6`으로 해요.
  - 6번: 충전 완료 화면이 아니면 장바구니에서 다시 주문해요.
  - 9번: 정산 대기 후보가 2건(이번 판매 대금 + 수수료)이 아니면 실행 전에 물어봐요. `--auto`면 실행하지 않고 멈춰요.

## 설정 (환경 변수)

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `DEMO_SCREEN_W` / `DEMO_SCREEN_H` | 1920 / 1080 (`demo.sh`는 1728 / 1080) | 화면 크기(논리 해상도) |
| `DEMO_WIDTH_RATIO` | 0.75 | 창 폭 (화면 폭 대비) |
| `DEMO_SCALE` | 1 | 화면 배율. 1보다 작으면 더 넓게 보여요(창 폭 ÷ 배율 ≥ 1024면 데스크톱 레이아웃) |
| `DEMO_SLOWMO` | 120 | 동작 사이 지연(ms) |
| `DEMO_PRESS` | 700 | 누를 곳을 강조한 뒤 누르기까지 기다리는 시간(ms) |
| `DEMO_BEAT` | 1500 | 새 화면에 들어선 뒤 쉬는 시간(ms) |
| `DEMO_HOLD` | 3000 | 결과 화면(가입·충전·주문 완료, 정산 등)을 보여 주는 시간(ms) |
| `DEMO_BASE_URL` | 운영 주소 | 다른 서버로 돌릴 때 |

예: 천천히 → `DEMO_BEAT=2500 DEMO_HOLD=5000 ./demo.sh`

## 주의

- **운영 DB에 데이터가 남아요.** 계정(`db…`·`ds…`), 상점·상품(`[시연] …`), 주문, 충전, 정산이 쌓여요. 정리할 땐 이 이름으로 찾아요.
- **정산 실행은 되돌릴 수 없어요.** 9번은 대기 중인 정산 후보를 모두 정산해요. 다른 사람 건이 섞여 있지 않은지 확인해요.
- 토스는 테스트 키라 실제 결제는 일어나지 않아요.
- 윈도우: `node run.mjs`로 실행해요(`demo.sh`는 Git Bash에서만). `--record`의 영상 폴더 경로는 아직 맥 기준이에요.

## 파일

| 파일 | 내용 |
|---|---|
| `demo.sh` | 실행 진입점(화면 크기 기본값) |
| `run.mjs` | 장면 진행·터미널 입력·이어 하기 |
| `scenes.mjs` | 장면별 화면 조작 |
| `lib.mjs` | 운영 API 호출, 창 띄우기·전환, 누르기·입력·쉬기 |
| `state.json` | 실행 중 생긴 계정·번호 (git에 안 올라가요) |
